Greedy algorithms build a solution one step at a time. At every step they make the choice that looks best right now and never go back to change it. This makes them simple to write and usually very fast, but it also means they only work for problems with a special structure. Two properties are needed. The first is the greedy-choice property: some optimal solution begins with the greedy choice. The second is optimal substructure: after making that choice, what remains is a smaller problem of the same kind, and an optimal answer to it combines with the first choice to give an optimal answer overall.

Activity selection is the classic example. If we always pick the activity that finishes first, we leave as much time as possible for the remaining activities, and an exchange argument shows that nothing is lost. The fractional knapsack problem behaves the same way: filling the bag with the item of highest value per kilogram can never be beaten, because any space used for a worse item could be traded for a better one. The 0/1 knapsack problem looks almost identical, yet the same rule fails, since an item cannot be cut and the space left over may be wasted.

Huffman coding is a greedy method for data compression. It repeatedly joins the two least frequent symbols into a new node whose weight is their sum, until a single tree remains. Frequent characters end up near the root and receive short codes, while rare characters sit deep in the tree and receive long codes. Because no code is a prefix of another, the encoded bit string can be decoded without any separators. For ordinary English text, where the letter e and the space are far more common than the letters q or z, this usually saves around forty percent compared with eight bits per character.

Graph algorithms provide more examples. Dijkstra's algorithm grows a set of vertices whose shortest distances are final, always adding the closest vertex outside the set. Prim's algorithm grows a minimum spanning tree in the same way, always adding the cheapest edge that leaves the tree, while Kruskal's algorithm considers all edges from cheapest to most expensive and keeps every edge that does not form a cycle. Each of these is correct only because of a proof that the greedy choice is safe; when the conditions of the proof are broken, for example by a negative edge weight in Dijkstra's algorithm, the answers can be wrong.

Randomized algorithms take a different approach. Instead of always making the same choice, they flip coins. Randomized quickselect picks a random pivot and finds the k-th smallest element in expected linear time, whatever the input order. The Miller-Rabin test checks whether a number is prime by trying random bases; each round that says prime can be wrong with probability at most one quarter, so a few rounds make an error extremely unlikely. In both cases the randomness protects us from inputs that were designed to be difficult.
